# Overview

This section covers what OpsPilot is, the estates it is built for, who uses it,
and what happens between your question and a command running on a server. Read
it before you install anything. If you are reviewing OpsPilot for a security
sign-off, start with [Architecture](architecture.md).

## The pages in this section

- **[What OpsPilot is](what-is-opspilot.md)** — the definition, the principle the
  product is built around, and how it differs from an AI coding tool.
- **[Why OpsPilot](why-opspilot.md)** — the capabilities that follow from
  reaching disconnected estates without giving a model a shell, with the
  mechanism behind each one and its limits.
- **[Who it is for](who-its-for.md)** — six roles, and what each one does with
  OpsPilot day to day.
- **[How it works](how-it-works.md)** — the eight-step loop from question to
  executed command, the two AI modes, and where each kind of data is held.
- **[Architecture](architecture.md)** — process separation, trust boundaries,
  data flow, and where configuration and credentials live. Written for an
  architect or a security reviewer.
